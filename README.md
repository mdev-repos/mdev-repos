## 🔍 Acerca de mí
</div>
<div align="justify">
  <p>
    Soy desarrollador de software y mi trabajo se reparte entre dos mundos que rara vez se cruzan. Por un lado hago backend con <strong>Java y Spring Boot</strong>, el ecosistema donde más horas de práctica acumulo. Por el otro trabajo con <strong>Mainframe y COBOL</strong>, una plataforma que sostiene buena parte de los sistemas críticos de bancos y grandes empresas y en la que cada vez hay menos gente que la conozca. Estoy terminando la Tecnicatura en Desarrollo de Software, me quedan cinco materias, y en paralelo sigo mi propio roadmap de especialización en backend, que incluye microservicios con Spring Cloud, seguridad con Spring Security, testing y Spring AI.
  </p>
  <p>
    Cuando arranco un proyecto de la carrera no empiezo por el código. Primero relevo los requerimientos, modelo los procesos con diagramas de flujo de datos, escribo los casos de uso y diseño la base de datos, y recién ahí abro el editor. Me importa mucho ese camino previo porque es lo que permite entender qué hay que construir y por qué, y en un perfil con mi experiencia no suele verse, ya que lo habitual es empezar directamente por el desarrollo. Los proyectos de este perfil muestran ese recorrido completo, desde el análisis hasta el sistema funcionando.
  </p>
  <p>
    Mi formación en <strong>Mainframe IBM</strong> la hice en CODEKI | UBA, durante siete meses de trabajo intensivo junto a profesionales del rubro, programando en COBOL, JCL, DB2 y CICS sobre mainframes reales disponibles las veinticuatro horas. Además me mantengo al día con las capacitaciones y certificaciones que ofrece IBM, lo que me permite seguir practicando sobre estas tecnologías tan robustas. Haber trabajado en las dos veredas, la de los sistemas modernos y la de los transaccionales de toda la vida, me ayuda a entender mejor cómo piensa cada una y de qué manera se conectan entre sí.
  </p>
  <p>
    Todavía no tengo experiencia laboral formal, así que lo que puedo mostrar es trabajo concreto. Eso incluye proyectos propios documentados de punta a punta, con análisis, diseño, código, tests y despliegue, además de algunos desarrollos freelance para terceros. Estoy buscando mi primera oportunidad en desarrollo y me interesan por igual los equipos de Java y los de Mainframe.
  </p>

## 🚀 Proyectos en Desarrollo

</div>

> **GymApp** se encuentra en desarrollo. Va a ser mi primera aplicación personal real pensada para llegar a producción y uso público: no es un ejercicio de práctica ni un trabajo freelance.

![GymApp](./assets/GymApp-Card.png)

API REST para una aplicación multiplataforma (web y mobile) pensada para organizar y ejecutar macrociclos y mesociclos de entrenamiento en el gimnasio. Stack: **Java + Spring Boot + PostgreSQL**, con la seguridad a cargo de **Spring Security**. Todavía sin repositorio público: se abre cuando tenga una primera versión desplegable.

<br>

> **NodoBank** se encuentra en desarrollo. Es la adaptación a un dominio propio del proyecto final del curso *Microservicios con Spring Cloud* (TodoCode Academy), elegido a propósito por lo exigente: el dominio financiero obliga a pensar en integridad de datos, concurrencia y trazabilidad. Con él demuestro el stack que domino y mis prácticas de análisis y desarrollo.

![NodoBank](./assets/NodoBank-Card.png)

Core bancario simplificado: administración de cuentas, transacciones (depósitos, retiros y transferencias) y notificación por email de cada operación confirmada. Construido como monorepo de microservicios con **Java 25 + Spring Boot 4 + Spring Cloud + MySQL**; la seguridad con **Spring Security + JWT** es el próximo hito.

- **Ya implementado**: Eureka Server (service discovery), Config Server (configuración centralizada) y `accounts-sv`, con arquitectura en capas, DTOs + Mapper, manejo centralizado de excepciones (`ProblemDetail`) y **optimistic locking** para proteger el saldo ante operaciones concurrentes.
- **En camino**:
  - **Seguridad stateless con Spring Security**: un `auth-sv` para usuarios, roles y contraseñas encriptadas (BCrypt) que emite el **JWT** (JJWT), con el API Gateway como único punto de validación del token y autorización por roles (`CUSTOMER` / `ADMIN`) con `@PreAuthorize` en los servicios.
  - `transactions-sv`: depósitos, retiros y transferencias, comunicándose con `accounts-sv` vía Feign con Circuit Breaker y Retry (Resilience4j).
  - `notifications-sv` (Spring Mail + Thymeleaf), API Gateway, Dockerización completa y tests.

> **Bazar** es el proyecto con código visible que mejor refleja mi nivel actual: está publicado y desplegado, y sigue recibiendo mejoras. Parte de un ejercicio práctico (TodoCode Academy) que llevé más lejos para demostrar mis habilidades técnicas, el stack que domino y mis prácticas de análisis y desarrollo.

[![Bazar](./assets/Bazar-Card.png)](https://github.com/mdev-repos/api_bazar__ejercicio_curso_todocode)

[![Repo](https://img.shields.io/badge/Repo-181717?style=flat-square&logo=github)](https://github.com/mdev-repos/api_bazar__ejercicio_curso_todocode)
[![API Live](https://img.shields.io/badge/API%20Live-46E3B7?style=flat-square&logo=render&logoColor=white)](https://api-bazar-ejercicio-curso-todocode.onrender.com)
[![Front Demo](https://img.shields.io/badge/Front%20Demo-00C853?style=flat-square&logo=rocket)](https://mdev-repos.github.io/front_bazar__curso_todocode/)

API REST para la gestión de ventas de un bazar: productos, clientes y ventas relacionados
entre sí, con reportes de negocio (bajo stock, monto vendido por fecha, venta más alta).
El modelado agrega una entidad `SaleItem` no pedida por la consigna, necesaria para
resolver correctamente la relación muchos-a-muchos entre venta y producto con datos
propios (cantidad, precio unitario, subtotal).

Construido con **Java 25 + Spring Boot 4**, arquitectura en capas (Controller → Service
→ Repository) con **DTOs + Mapper**, manejo centralizado de excepciones (`ProblemDetail`
/ RFC 7807), y refactor completo a **programación funcional** (Streams). Dockerizado
(`Dockerfile` + `docker-compose.yml`) y deployado de punta a punta: backend en Render,
base de datos en Neon (PostgreSQL), front propio consumiéndolo en vivo desde GitHub Pages.

<br>
